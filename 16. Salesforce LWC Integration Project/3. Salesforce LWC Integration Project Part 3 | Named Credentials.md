# 📖 Overview

In the previous part, we learned how to integrate an external REST API using **Remote Site Settings**.

However, Remote Site Settings require developers to manually manage authentication inside Apex.

Salesforce provides a better and more secure solution called **Named Credentials**.

Named Credentials store the API endpoint and authentication information in one place, making integrations easier, safer, and easier to maintain.

# 📖 Actual Definition (Based on the Video)

### Named Credentials

A **Named Credential specifies the URL of a callout endpoint and its required authentication parameters in one definition.**

Salesforce manages the authentication automatically, so developers do not need to write authentication logic inside Apex.

---

# 💡 Simple Definition

Think of Named Credentials as a **secure locker** where Salesforce stores:

- API URL
- Username
- Password
- API Key
- OAuth Tokens
- Authentication Details

Whenever Apex needs to call an external API, Salesforce automatically retrieves these credentials and sends them securely.

Developers only reference the **Named Credential** instead of writing sensitive information in code.

# Remote Site Settings vs Named Credentials

There are **two ways** to authorize an API domain in Salesforce:

1. Remote Site Settings
2. Named Credentials

---

## Difference

| Remote Site Settings | Named Credentials |
|----------------------|-------------------|
| URL is registered in Salesforce Org. Authentication headers have to be mentioned in the program. | A Named Credential specifies the URL of a callout endpoint and its required authentication parameters in one definition. |
| Apex developer has to manage authentication. | Salesforce manages the authentication automatically. |
| Maintenance is difficult if changes occur in the future. | Maintenance is easy because changes are made in one place only. |

# Step-by-Step Configuration

## Step 1 — Open Named Credentials

Go to

```
Setup

↓

Search

↓

Named Credentials
```

---

## Step 2 — Create External Credential

Click

```
External Credentials

↓

New
```

Fill in the required details:

- Label
- Name
- Authentication Protocol → **Custom**

Click **Save**.

---

# What is an External Credential?

An **External Credential** defines **how Salesforce authenticates** with an external system.

It stores authentication-related information but does not contain the API endpoint.

---

## Step 3 — Create Principal

After saving the External Credential,

scroll down to the **Principals** section.

Click

```
New
```

Provide the required information, such as:

- Parameter Name
- Authentication details

Save the record.

---

# What is a Principal?

A **Principal** represents the identity Salesforce uses while communicating with an external service.

It contains the authentication parameters required by the API.

---

## Step 4 — Create Named Credential

Go back to

```
Named Credentials

↓

New
```

Fill the required details:

- Label
- Name
- URL (API Endpoint)
- Select the External Credential created earlier

Save.

---

# What Does the Named Credential Store?

A Named Credential stores:

- Endpoint URL
- Authentication Configuration
- External Credential Reference
- Authentication Protocol
- Connection Details

# Best Practices

✅ Use Named Credentials instead of Remote Site Settings for new integrations.

✅ Never hardcode API Keys or passwords in Apex.

✅ Reuse Named Credentials across multiple Apex classes.

✅ Store authentication securely using External Credentials.

✅ Keep authentication logic out of Apex code.

---

# Common Mistakes

❌ Hardcoding API Keys in Apex.

❌ Using Remote Site Settings for complex authentication.

❌ Creating multiple Named Credentials for the same API unnecessarily.

❌ Forgetting to associate the correct External Credential.

❌ Not testing the connection after configuration.

# Interview Questions

### 1. What is a Named Credential?

A Named Credential specifies the URL of a callout endpoint and its required authentication parameters in one definition.

---

### 2. Why do we use Named Credentials?

To securely store API endpoint and authentication details while allowing Salesforce to manage authentication automatically.

---

### 3. What is the difference between Remote Site Settings and Named Credentials?

Remote Site Settings only authorize the endpoint, while authentication must be handled in Apex. Named Credentials combine the endpoint and authentication into a single configuration managed by Salesforce.

---

### 4. Who manages authentication when using Named Credentials?

Salesforce manages authentication automatically.

---

### 5. What is an External Credential?

An External Credential defines how Salesforce authenticates with an external system.

---

### 6. What is a Principal?

A Principal represents the identity Salesforce uses to authenticate with the external system.

---

### 7. Why are Named Credentials considered more secure?

Because sensitive information such as API Keys, passwords, and tokens are stored securely instead of being hardcoded in Apex.

# Key Takeaways

- Named Credentials are the modern and recommended way to connect Salesforce with external APIs.
- They combine the endpoint URL and authentication configuration into a single reusable definition.
- Salesforce automatically handles authentication, reducing the amount of Apex code developers need to write.
- External Credentials define the authentication method, while Principals provide the authentication identity.
- Named Credentials improve security, simplify maintenance, and make integrations easier to manage.
